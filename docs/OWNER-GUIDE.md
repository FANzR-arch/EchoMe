# Echome 主人使用说明

日常只需要记住：**和 AI 聊 → 确认保存 → 发布到线上**。看访客的问题时，再打开「线上存档」。

## 1. 打开后台

后台目前只在你的电脑运行。网页打不开时，在项目目录运行：

```powershell
npm run dev:admin
```

保留这个终端窗口，打开 http://127.0.0.1:5175/admin/interview 。线上访客聊天不依赖你的电脑开机。

## 2. 自己和 AI 聊，补充个人资料

进入「和我的 AI 聊聊」，首次点「开始聊聊」。AI 会根据已有资料提问并拟答，你可以：

- 觉得准确：点「准确，保存」。
- 有误：直接说清楚，例如「这个项目我主要负责设计，不是开发，请修正」。
- 想换话题：点「先跳过」，或输入「接下来聊我的合作方式」。
- 保存错了：点「撤销刚才保存」，也可以输入「撤销刚才的修改」。

可以直接这样开聊：

> 你模拟一个第一次看到我网站的人，问我一个最想了解的问题。根据已有资料先拟答，等我确认，再问下一题。

只有你确认的拟答才写入知识，普通聊天不自动成为事实。这里使用你本机已登录的 **Codex CLI** 和其账户额度；访客聊天使用 **DeepSeek API**，两者分开。

## 3. 看访客聊了什么

打开 http://127.0.0.1:5175/admin/conversations ，点击上方「线上存档」。

选一条记录，可以看原问题、原始回答、实际使用的资料、耗时和 token 用量。「批注」「纠正」供你审核，不会改写访客已经收到的回答，也不会自动改知识。

如果发现 AI 答错：复制正确说法，回到交流页告诉 AI「请根据这个纠正更新相关资料」，检查拟答后确认保存。也可以直接到「资料与人设」修改对应资料。

「对话审核」里的原有记录是本机测试记录；真正线上访客的记录看「线上存档」。列表每页最多 100 次请求，可翻页；重试也会有独立请求记录。

## 4. 修改知识和人设

打开 http://127.0.0.1:5175/admin/knowledge ：

- 「资料与人设」：编辑介绍、作品、人设、规则；保存后按启用状态供本机回答使用。
- 「核心资料」：每次完整提供，总计不能超过 4,000 字符。
- 「详细资料」：模型需要时读取；较长作品和文章放这里。
- 「版本记录」：出错时回退。

未确认的拟答、停用的资料不会进入线上发布包。访客对话不会自动变成你的观点。

## 5. 让修改在线上生效

**本机保存不等于线上发布；Git push 也不等于发布最新知识。** 当前线上 AI 使用你明确导出的资料包。

最省事的方式：告诉 Codex **「把我确认的最新资料发布到线上 AI，并检查一次配置，不调用模型」**。

自己操作则在项目目录运行：

```powershell
npm run knowledge:export
# 查看 deploy/knowledge-release.json，确认内容可供访客回答使用
npm run build:cloud
vercel deploy --prod --yes --scope fanzr-archs-projects
```

导出和构建不消耗模型额度。部署完成后，新回复使用新版；旧存档仍保留回答当时的资料快照。资料包默认不提交 Git，所以暂不依赖 Git 自动部署来更新知识。

## 6. 自动清理和费用

在「线上存档」顶部设置保留期限：7 天、30 天、90 天，或关闭自动删除。

默认按**会话最后一次交流**计时；超过 7 天未活动后，每小时任务会删除整段会话、重试记录和批注。知识库、人设、本机记录以及访客浏览器历史不受影响。删除后不能从工作台恢复。

目前全站每天最多 30 次有效聊天请求，每分钟 6 次、并发 2 次。用于控制模型消耗，不是每个访客各 30 次。免费托管额度和模型费用是两回事；Supabase 免费项目长期无活动可能暂停。

## 7. 常用入口与备份

- 个人网站：owner.config.json 里的 `site`
- 独立聊天：你部署的聊天站，例如 https://YOUR-CHAT-SITE/chat
- 本机交流：http://127.0.0.1:5175/admin/interview
- 本机资料：http://127.0.0.1:5175/admin/knowledge
- 本机存档：http://127.0.0.1:5175/admin/conversations → 线上存档
- 云数据库：你的 Supabase 项目控制台

Git 保存程序代码，不保存密钥、本机聊天、访谈草稿和 SQLite 人工修改。搬电脑前，关闭本机开发服务，再私下备份 `.local-data` 目录与 `.env.local`；不要把它们放进公开仓库。
