# 整理 EchoMe 资料（给 AI 执行）

> 用户会对你说：“请按这份说明帮我整理 EchoMe 的资料。”你是用户自己的 AI 助手。网站 AI 只根据这些资料回答访客，所以只写有依据的事实。

## 步骤

1. **先问用户**：要参考哪些公开来源（个人网站、社交主页、作品集、文章），有没有想补充的文件。只看用户给的来源和公开页面，不要搜索用户的私人信息。
2. **按类别整理**，每条一个主题：
   - 个人介绍
   - 联系方式
   - 作品：每个作品一条，写清做了什么、给谁用、用户负责什么
   - 文章：每篇一条，写清讲了什么
   - 服务与合作方式
   - 常见问题
3. **写法**：第三人称的事实陈述，附上来源链接（完整的 `https://` 地址）。个人介绍和联系方式标为「每次都带上」，这两类合计不超过 4000 字；其他都是「需要时读取」。
4. **拿不准的不写**：不确定的、来源互相矛盾的、用户可能不想公开的内容（报价、档期、客户名称、私人经历），不要写进资料，列成「待你确认的问题」问用户。
5. **写入**：
   - 能用 EchoMe 的 `draft_knowledge` 工具：每条用它写进待确认区，来源和疑问写在 `note` 里。不要用 `update_knowledge` 直接上线。
   - 不能用：按下面「资料文件格式」生成一个 Markdown 文件交给用户，请用户在后台「它知道什么 → 上传文件」导入。
6. **告诉用户**：一共整理了几条、待你确认的问题有哪些，以及去哪里检查：后台 `https://<聊天站>/owner` →「待处理」，逐条「确认上线」、修改后确认，或「丢弃」。没确认的不会被网站 AI 使用。

## 资料文件格式

每条资料以 `## 标题` 开头；`链接：`、`每次都带上`、`备注：` 三行可选，其余为正文；标题为「待你确认的问题」的部分不会导入。

```markdown
## 个人介绍
链接：https://wang.example.com/about
每次都带上
备注：来自关于页
小王是一名独立设计师，主要做品牌视觉和网站设计。

## 作品：咖啡品牌官网
链接：https://wang.example.com/projects/coffee
为一家咖啡品牌设计并搭建官网，小王负责视觉设计和前端开发。
```
