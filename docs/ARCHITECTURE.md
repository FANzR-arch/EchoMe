# 架构与运行细节

本文是 README 的展开版：本机工作台、资料使用方式、预算与限流、数据边界和项目结构。

## 最简单的用法：和我的 AI 聊聊

打开管理站默认进入交流页。点“开始聊聊”，真实 Codex 会先根据已有资料提出一个问题，并拟好答案。你只需点“准确，保存”、直接纠正，或跳过。也可以输入“准确，保存”；保存后输入“撤销刚才的修改”即可回退。AI 模拟的问题和未确认拟答不会自动成为知识。

每次发送调用本机 Codex 账户，最多两分钟；每次一个问题，不要求先选模式或找到资料。公开聊天 API 的配置与此入口无关。交流与待确认草稿保存在本机 SQLite，刷新恢复；只在明确确认后发布，冲突会拒绝覆盖。

第一版提供最多 50,000 字符的完整资料集合及目录，优先初始核心包和既有资料；未完整提供的资料不可作为拟答依据。最近 8 条交流用于当前轮，完整记录仍保留；单会话最多 200 条，未做长期自动摘要。选择已有资料更新或新增详细问答，来源沿用实际提供的资料，不自动抓取外网。

常用导航收为“和我的 AI 聊聊”和“资料与记录”。原高级界面保留在原路径。

## 需要时再打开的资料与记录

1. **资料与人设**：首先查看“核心资料包 · 待主人审核”。草稿来自网站公开介绍、主要作品和公开联系渠道，默认停用。核对后勾选启用并保存。个人观点只添加你认可的说法，不从访客聊天推断。
2. **编辑资料**：选择核心／详细分类、来源、正文和启用状态。有效核心正文总计最多 4,000 字符，超出拒绝保存，不截断。外部调研固定作为详细资料。
3. **检查回答依据**：不调用模型，直接查看每次完整提供的核心正文和可按需读取的详细目录。这不是模型实际检索结果。
4. **对话审核**：真实模式的新请求按会话和问题尝试归组；查看原始回答、当时的正文快照、耗时与实际用量，另存批注和正确说法。审核不修改原回答，也不自动更新知识。
5. **AI 修改提案**：选资料、写要求，再选择是否主动附加当前审核对话。Codex 生成的是草稿；检查前后文本，可以编辑，再确认启用。也可以复制任务给 Grok，把完整正文粘回提案。不开发第二套 CLI。
6. **版本记录**：可恢复修改前的版本；回退新增资料会停用该条目。提案生成后原资料若已变化，拒绝覆盖，需刷新后重新核对。

网站更新后执行 `npm run knowledge:sync`。手动覆盖的资料不会被同步覆盖，显示“网站有更新”，可对照后采用新网站正文；也可保留人工版本。核心包作为派生草稿需要你人工核对来源变化。被网站删除、改为草稿的条目不再进入回答；依赖被撤回来源的核心包也暂停提供。

人设和回答规则的有效版本可在工作台编辑。固定身份边界始终由服务端提供：“我”指 AI 助手，按 owner.config.json 的中英文称呼指代主人，不把访客当作主人；不编造事实、观点、报价、联系方式或合作承诺，资料不足说明无法确认。

## 回答如何使用资料

每次请求先识别意图和回答深度：精准的问候/寒暄/天气用本地规则，其余用同一固定模型的一次 JSON 分类（最多 96 输出 tokens）。问候、闲聊、实时查询、隐私、澄清分别使用短答方式；工作、项目、联系进入资料回答；咨询与普通知识按问题处理。复杂比较、推理、分析进入 thinking，简单事实进入 direct。分类仅作为辅助：格式错误、分类服务失败或超过 4 秒时，跳过分类，按通用资料回答路径继续，不要求访客重试分类。停止按钮会取消整个流程，不触发兜底生成。只有本地规则或模型明确确认无法理解时才使用三种中英文固定澄清短句，标记为 local-preset，绝不作为模型生成内容或个人事实。模型服务本身不可用时仍如实报告连接或额度问题。

完整规则和有效核心资料每次都提供；只有资料类路由附详细目录（编号、标题、类型、短摘要）。工作、项目、联系类每轮要求读取正文，不能仅把历史 AI 回答当成事实；咨询按需读取。需要深入阅读时，模型可调用一次 `read_knowledge`，一次最多两个已启用资料编号，每份最多 6,000 字符，附带截断标记。不能指定 URL、文件路径或命令。引用链接只允许来自本次实际提供的正文来源及 owner.config.json 中主人确认的联系入口。联系回复优先使用该入口的 Markdown 链接。消息支持 Markdown 加粗、列表、引用、代码和表格，外链在新标签打开；不执行 HTML 或危险链接。无法核对的 URL 不提供跳转，不显示内部校验占位文字。

不用向量数据库、嵌入模型或大型 RAG 平台。目录的语义选择交给聊天模型；能否正确选择及遵守规则必须在选定模型后做真实准确性验收。模型不自动上网。

输入上限 2,000 字符、最多 24 条历史消息、完整序列化上游请求最多 36,000 字符。核心资料不会因预算不足被省略，超限直接报错。直接模式按意图限制为 100–600 输出 tokens；有工具时首轮最多 256，第二轮使用剩余额度。思考模式使用 DeepSeek `thinking: enabled`、`reasoning_effort: low`，总生成预算最多 3,072 tokens（包含思考和正文）；工具首轮 1,024、第二轮 2,048。分类额度另计 96。推理原文仅在内存中用于同一轮工具协议，不展示、不存审核记录；工具读取前的过程说明也不进入访客回答。资料选择阶段只调用工具或返回 READY；最终正文在独立阶段逐段发送，不等待完整答案。输入框底部不显示模式标签或对话说明；数据边界见本文“数据与边界”。思考达到额度而未给正文会明确报错。

每个聊天服务进程：并发 2、每分钟最多 6 次尝试、UTC 每日 30 次对话尝试（每次最多三次上游请求：分类、资料读取请求、最终回答）；总超时 45 秒，流空闲 12 秒。本机计数重启清零；云端另有 Supabase 原子额度计数，重启和删除会话不会清零。工作台兼容性检查独立限为每分钟一次，不计入聊天计数。停止会取消当前上游与整个读取流程，保留已生成文字；不自动重试付费请求。

## Codex CLI

先在本机安装并登录 Codex，`codex login status` 应显示已登录。默认读取 npm 安装位置；特殊位置可设置服务端 `PAI_CODEX_JS`。程序使用只读沙箱、关闭 shell、多代理、apps、plugins 和 memories，忽略通用用户配置，只沿用本机顶层模型名与登录凭据；通过 HTTP Responses 连接，不启动全套个人工具。

如果网络需要代理，在 `.env.local` 设置 `PAI_CODEX_PROXY=http://127.0.0.1:实际端口`，可用 `PAI_CODEX_MODEL` 显式覆盖 CLI 模型。此变量只用于 Codex，不是聊天 API 配置。

单任务最多两分钟；取消和超时使用 Windows `taskkill /T /F` 停止进程树。服务正常关闭时取消任务，重启后中断状态落库，不自动重试。强制结束父进程或断电不能保证退出回调执行。CLI 实际用量包含自身系统上下文，不能用资料字数推算费用。原始 stdout/stderr 不记录，只保留筛选后的状态和数字指标。

## 数据与边界

- SQLite 位于 `.local-data/workbench.sqlite`；CLI 结果位于 `.local-data/cli/`，均不进入 Git。备份前停止服务，并备份整个 `.local-data` 目录。
- 资料文件是初始来源，SQLite 保存人工覆盖及修订。发布资料和标记提案已应用在同一事务提交。
- 浏览器保留历史且不跨设备同步。真实请求同时发送给配置的模型服务商，本机开发请求留存在本机供主人审核，默认保留至主人删除；线上请求留存在 Supabase，默认清理超过 7 天未活动的整段会话。旧浏览器历史和模拟对话不导入。
- 「删除整个会话审核记录」删除该会话的所有请求及批注，不删除浏览器历史。此前主动附入提案的资料属于提案内容，不随审核记录自动删除。
- 第一版列表显示最近 200 条请求、100 条提案／修订；底层数据不会因此自动删除。用量缺失显示缺失，不当作零。
- 管理接口仅由独立管理站提供，检查 loopback、同源与临时会话令牌。公开站不能下载服务端源码、资料、数据库或 CLI 输出。来源检查不是生产登录认证，勿对外开放开发端口。
- 留言、反馈和旧演示设置保留其演示边界，不发送邮件或通知。

## 验证与项目结构

```powershell
npm run knowledge:sync
npm run knowledge:check
npm run test:server
npm run test:knowledge
npm run build
$env:PW_CHANNEL='msedge'
npm test
```

自动化使用假模型上游，**不使用假 CLI 宣称集成成功**。浏览器测试使用隔离的 `.workbench-test-data`，需先关闭占用 5173–5175 的开发服务。构建输出是静态站点；`vite preview` 不提供本机 API。

- `server/knowledge.ts`：资料加载、核心包、目录与受限读取。
- `server/api.ts` / `completion.ts`：固定上游、流式对话、工具往返、取消与审计。
- `server/intent.ts` / `provider.ts`：意图与直接/思考路由、DeepSeek 协议选项。
- `server/capability.ts`：配置绑定的真实工具兼容性检查。
- `server/workbench-*.ts`：SQLite、管理接口、真实 Codex 进程。
- `src/pages/workbench.tsx`：复用现有管理壳的工作台。
- `src/lib/model.ts`：现有聊天组件的真实适配器；`src/lib/mock.ts` 保留模拟回归。

详见 [资料说明](../knowledge/README.md)、[双站和嵌入协议](SEPARATE-SITES.md)。线上管理员登录和通知仍未实现。本机资料确认后只影响本机回答；公开站使用经过审核并重新部署的资料包。

## 云端部署：Vercel + Supabase

本机工作台继续保留；云端仅部署公开聊天与模型 API。新增「线上存档」可查看云端原始回答、资料与用量，保存批注或删除整个会话。默认清理超过 7 天未活动的会话及批注，可改为 30/90 天或关闭；知识与本机记录不受影响。

- `npm run knowledge:export`：导出已启用资料、人设与规则，不含聊天和草稿。
- `npm run build:cloud`：检查发布包并构建公开站。
- 云端所需环境变量、SQL、Cron 和使用边界见 [Vercel + Supabase 部署说明](VERCEL-SUPABASE.md)。
- 服务端密钥只填本机 `.env.local` 与 Vercel 环境变量。不要放进浏览器变量或 Git。
