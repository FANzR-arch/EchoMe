# 个人资料维护

这里是虚构的示例资料。换成你自己的：复制整个目录为 `knowledge.local/`，在 `.env.local` 设置 `PAI_KNOWLEDGE_DIR=knowledge.local`。

推荐从本机工作台维护，不需要学习数据库操作。完整启动与工作台流程见 [README](../README.md)。

## 文件与工作台关系

- `persona.md`、`rules.md`：初始人设和回答规则。工作台启用的覆盖版优先，下一次请求生效。
- `website/snapshot.json`：网站公开内容同步快照，不手改；工作台覆盖版本另存 SQLite。
- `approved/*.md`：可选的主人批准资料，JSON 头部须为 `approved: true`。research 是外部调研，不等于主人的观点。
- `templates/`：给 Codex / Grok 的可复制任务和资料模板，不参与回答。

运行 `npm run knowledge:sync -- --site "网站目录"`（或在 `.env.local` 设置 `PAI_SITE_DIR`）只读取网站的公开介绍、联系渠道、作品和全文且非草稿的文章。复用网站已安装的 YAML 解析器，不修改网站。根据本地发布标记导入，不代表逐个验证过线上 URL。

同步保留人工覆盖，来源内容变化会显示“网站有更新”。已删除、改草稿或撤销批准的源资料不再提供。已经启用的核心草稿若依赖被移除的源，也不会提供，须重新核对。

## 核心与详细资料

首次核心草稿包括公开介绍、主要作品简述及角色、公开联系渠道和无法确认时的边界；未经主人启用不进入请求。有效核心正文合计不超过 4,000 字符，每次完整提供。

详细资料先只提供目录，由模型申请按编号读正文。最多一轮、两份，每份最多 6,000 字符，标明截断。工作台的免费检查只展示完整核心和目录，不声称模型已选中或读过文章。`npm run knowledge:check -- --query "做过哪些时间管理工具"` 也不调用模型。

## 添加 Agent 调研

在工作台新增外部调研并填写真实 HTTPS 来源，或把审核过的 Markdown 放入 approved。文件元信息范例见 [agent-note.md](templates/agent-note.md)。资料应适合向访客公开；不要附密钥、私人聊天或未经确认的经历。

CLI 只接收当前选择的资料、修改要求及主动勾选附加的审核对话。它只能提出草稿，确认前不影响回答。访客反馈和审核批注不会自动学习成知识。

模型是否正确理解、引用和拒绝无依据问题仍需真实准确性验收；规则不是模型永不出错的保证。
